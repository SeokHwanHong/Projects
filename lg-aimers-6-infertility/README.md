# LG Aimers 6기 — 난임 환자 임신 성공 예측

[블로그 프로젝트 글](https://seokhwanhong.github.io/projects/lg-aimers-infertility/)

LG Aimers 6기 온라인 해커톤에서 난임 시술 기록으로 임신 성공 여부를 예측한 팀 **뭉치네 밥버거**의 프로젝트다. 데이터의 범주와 결측 패턴을 분석하고, 시술·난자·배아 정보를 연결한 파생변수를 만든 뒤 CatBoost·LightGBM·AutoGluon의 예측을 결합했다. 기존 포트폴리오에 기록된 성과는 **예선 상위 3%, 오프라인 본선 진출**이다.

이번 글은 보존된 팀 발표자료, 데이터 명세, 실험 메모, 학습 로그와 제출 예측 파일을 대조해 정리했다. 학습을 다시 실행한 결과가 아니라 당시 자료에서 확인되는 분석 과정과 결과를 설명한다.

## 1. 문제와 데이터의 규모

목표는 시술별 `임신 성공 여부`를 예측하는 것이다. 데이터 명세에서 타깃은 0이 임신 실패, 1이 임신 성공이다. 시술 이력, 연령대, 불임 원인, 난자·정자 출처, 배아 생성·이식 정보가 함께 들어 있다.

| 자료 | 행 수 | 열 수 | 의미 |
| --- | ---: | ---: | --- |
| 원본 `train.csv` | 256,351 | 69 | ID, 입력 변수 67개, 타깃 1개 |
| 원본 `test.csv` | 90,067 | 68 | ID와 입력 변수, 타깃 없음 |
| 보존된 `train_df.csv` | 256,351 | 111 | 전처리·파생변수 포함 중간 산출물, 타깃 포함 |
| 별도 실험 메모 | 126,244 | 메모별 상이 | 일부 전처리 실험의 자료형·결측 기록 |

126,244행은 메모에 등장하는 규모이며 원본 학습 데이터 전체의 행 수가 아니다. 중간 산출물의 111열도 최종 모델에 모두 사용됐다는 뜻은 아니다. 최종 학습 코드와 피처 목록이 없어 마지막 입력 구성을 확정할 수 없다.

원본 학습 자료의 타깃 분포를 다시 집계하면 실패 190,123건, 성공 66,228건으로 성공 비율은 약 **25.83%**다. 다수 클래스만 따라가는 예측을 피하고 성공 사례도 학습에 반영하기 위해 모델 최적화 과정에서 클래스 가중치를 사용했다.

## 2. EDA에서 먼저 확인한 범주와 결측의 의미

### 숫자처럼 보여도 범주로 주어진 정보

`총 시술 횟수`에는 `0회`부터 `6회 이상`까지의 범주가 있다. 반면 `이식된 배아 수`는 명세상 수치형이지만 값의 종류가 제한돼 있어 범주로도 표현할 수 있었다. 팀은 변수의 원래 자료형만 따르기보다 수치의 크기와 범주별 차이를 함께 반영하는 방향을 검토했다.

![발표자료의 이식된 배아 수 분포](images/transferred-embryos-distribution.png)

*발표자료 3쪽에 제시한 이식된 배아 수 분포. 원본 그림을 추출했다.*

![발표자료의 총 시술 횟수 분포](images/treatment-count-distribution.png)

*발표자료 3쪽의 총 시술 횟수 분포. 횟수의 범주별 빈도를 확인했다.*

메모에는 이전 총 임신 횟수의 `6회 이상`이 3건, 이전 총 임신 성공 횟수의 같은 범주가 2건으로 기록돼 있다. 이 수치는 126,244행 실험 메모의 분포다. 드문 상위 범주를 5 또는 6으로 처리하는 방안을 검토했지만, 최종 처리 규칙은 남아 있는 메모만으로 확정되지 않는다.

발표자료에는 범주형 47개·수치형 28개라는 집계가 있다. 첨부 명세의 67개 입력 항목과 총수가 달라 이 값을 원본 스키마의 변수 수로 사용하지 않았다. 명세의 범주형 표시를 집계하면 범주형 46개, 수치형 20개, 별도 표시 1개다. 데이터 전체 규모와 특정 분석 단계의 변수 수를 구분하는 것이 필요했다.

### 함께 비어 있는 배아 변수

발표자료는 배아 관련 변수들이 동일한 행에서 함께 결측이라는 점을 파생변수 설계의 단서로 삼았다. 메모에서는 `DI` 시술의 난자 출처가 알 수 없고, 정자 출처는 기증 제공으로 기록되는 사례를 확인했다.

![발표자료의 변수별 결측 분포](images/missing-values-original.png)

*발표자료 4쪽의 결측 분포. 배아 관련 변수의 공통 결측 패턴을 확인하는 데 사용했다.*

이번에 원본 학습 CSV를 재집계한 결과, DI는 6,291행, IVF는 250,060행이다. 아래 다섯 변수는 DI의 모든 행에서 결측이고 IVF에서는 결측이 없었다.

| 변수 | DI 결측률 | IVF 결측률 |
| --- | ---: | ---: |
| 총 생성 배아 수 | 100% | 0% |
| 이식된 배아 수 | 100% | 0% |
| 저장된 배아 수 | 100% | 0% |
| 수집된 신선 난자 수 | 100% | 0% |

이는 결측을 해석할 때 시술 유형을 함께 봐야 한다는 근거다. 평균으로 일괄 대치하기 전에 해당 정보가 생성되는 과정과 기록 방식을 확인해야 했다. 관찰된 결측 패턴만으로 모든 행의 결측 원인을 임상적으로 확정하지는 않았다.

## 3. 전처리와 파생변수 설계

### 시술 문자열 정리와 미관측 범주

발표자료 5쪽에서는 동일한 시술 조합에서 공백 차이가 발생하는 것을 확인하고 특정 시술 유형의 공백을 제거했다. 인코딩에는 LabelEncoding을 사용했으며, 테스트에만 존재하는 시술 유형은 `Unknown`으로 처리했다고 기록했다.

결측은 부스팅 모델의 처리 기능을 활용하고 일괄 대치하지 않는 방향으로 설명돼 있다. 다만 수치형 결측과 범주형 결측의 실제 코드 처리 방식은 구분해서 확인해야 한다. 이번 압축파일에는 최종 전처리 코드가 없어 모델별 결측 전달 형식을 그대로 재현할 수는 없다.

### 시술·난자·배아의 관계를 변수로 연결

발표자료는 난자 활용, 미세주입, 배아 저장·해동, 시술 이력과 불임 원인의 조합을 파생변수 주제로 제시했다. 보존된 중간 CSV와 메모에는 다음 설계가 남아 있다.

| 주제 | 보존 자료에서 확인한 예 | 의미와 확인 범위 |
| --- | --- | --- |
| 불임 원인의 동시 발생 | `불임 원인 세부 합계`, `부부 불임 원인 합계` | 여러 원인 플래그를 합산. 세부 합계는 메모에 산식도 존재 |
| 난자·배아 활용 | `ICSI 효율`, `신선 난자 활용률`, `배아 저장 비율`, `총 난자 수` | 중간 CSV에 열 존재. 최종 모델에서의 기여도는 미기록 |
| 수량 간 차이·조합 | `생성-저장 배아 차이`, `저장-이식 차이`, `이식수x이식일수` | 개별 수량을 조합한 표현 |
| 수치·범주 동시 표현 | 이식 수·미세주입 이식 수·이식 경과일·저장 수의 `_num`, `_cate` | 발표자료와 중간 CSV에서 함께 확인 |
| 시술 이력 | 이전 IVF·DI 횟수 합, 신규 시술 여부 | 별도 메모의 설계안. 중간 CSV와는 다른 실험 기록 |
| 출처와 연령 조합 | 난자·정자 출처와 기증자 나이 결합 | 메모에 범주 결합 산식 존재 |

수치·범주 이중 표현은 값의 크기를 이용하는 분할과 특정 값의 범주적 차이를 함께 학습할 수 있게 하려는 접근이다. 원본 피처를 두 방식으로 표현하므로 열이 늘어나는 만큼 변수 중요도와 교차검증 결과를 함께 확인해야 한다.

메모에는 서로 다른 데이터프레임 이름을 혼용한 산식과 분모가 0이 될 수 있는 비율도 있다. 그래서 메모의 코드를 바로 실행 가능한 최종 코드로 옮기지는 않았다. 비율 변수는 0·결측 분모 처리 규칙과 학습·평가 자료에 같은 변환을 적용했는지 확인해야 한다.

## 4. Optuna와 5-fold 모델 최적화

팀은 CatBoost와 LightGBM의 하이퍼파라미터를 Optuna로 탐색했고, 탐색 시 **5-fold 교차검증**을 사용했다. 발표자료에 기록된 대표 설정은 다음과 같다.

| 설정 | CatBoost | LightGBM |
| --- | --- | --- |
| 반복 수 | `iterations=1375` | `n_estimators=300` |
| 학습률 | 약 0.04328 | 약 0.04748 |
| 깊이 | `depth=9` | `max_depth=5` |
| 잎 관련 설정 | `min_data_in_leaf=28` | `num_leaves=14`, `min_child_samples=50` |
| 불균형 처리 | `scale_pos_weight=3` | `class_weight="balanced"` |
| 평가 지표 | `AUC` | `auc` |

전체 파라미터는 GitHub의 [실험 기록](https://github.com/SeokHwanHong/Projects/tree/main/lg-aimers-6-infertility)에 정리했다. 이 설정은 발표자료의 결과이며, 보존된 CatBoost 로그와 동일한 실행이라는 근거는 없다. 로그 메타데이터에는 계획 반복 수 1,200이 기록돼 있고 실제 저장된 행은 408개다.

5-fold 탐색을 수행했다는 기록은 있지만 fold별 점수, Optuna trial 목록과 최종 학습 코드는 없다. 따라서 평균 CV 점수나 모델별 개선 폭을 추가로 만들어 넣지 않았다.

## 5. 학습 로그에서 확인되는 성능 변화

보존된 `test_error.tsv`는 `iter`, `AUC`, `Logloss`를 기록한다. 로그에서 `test`는 학습 중 평가한 자료의 이름이며, 타깃이 없는 대회 `test.csv`의 리더보드 점수를 뜻하지 않는다.

| 로그 시점 | iter, 0부터 시작 | AUC | Logloss |
| --- | ---: | ---: | ---: |
| 첫 기록 | 0 | 0.676561 | 0.691083 |
| **최고 AUC** | **397** | **0.723708** | 0.513039 |
| 마지막 기록 | 407 | 0.723650 | 0.512495 |

![CatBoost 평가 AUC 변화와 최고 기록](images/catboost-validation-auc.png)

*이번 자료 정리 과정에서 보존 로그 408행으로 다시 그린 곡선. 원래 학습 실행을 다시 수행한 그래프는 아니다.*

기존 글은 마지막 기록을 최고 AUC로 설명했는데, 로그 전체를 대조하면 최고점은 `iter=397`이다. 그 뒤 Logloss는 마지막까지 더 낮아졌지만 AUC는 최고점보다 약간 낮아졌다. 서로 다른 지표의 최적 시점을 구분해야 한다.

## 6. 세 모델의 확률을 결합한 최종 제출

발표자료 8쪽은 최적화한 CatBoost·LightGBM과 AutoGluon의 예측을 **동일 가중치 산술 평균**으로 결합했다고 명시한다. AutoGluon의 기록된 설정은 `num_trials=5`다. 공개된 자료로 확인되는 최종 결합은 확률 평균이며, 별도 메타 모델을 학습하는 스태킹으로 기술할 근거는 없다.

`p_final = (p_catboost + p_lightgbm + p_autogluon) / 3`

![CatBoost·LightGBM·AutoGluon 제출 확률 분포](images/submission-probabilities.png)

*첨부 제출 CSV의 예측값을 동일한 구간으로 재집계한 분포. 예측 분포 차이를 보여주며, 정답이 없어 이 그림만으로 성능 우열을 판단할 수는 없다.*

| 제출 파일 | 기록 |
| --- | --- |
| `bo_cb.csv` | CatBoost 예측. 저장 인덱스 열 `Unnamed: 0`도 포함 |
| `submission_lgbm_250225.csv` | LightGBM 예측 |
| `baseline_auto.csv` | AutoGluon 예측 |
| `lg_submission_cat_lgbm_auto_250225.csv` | 세 모델 평균 제출 |

이번 대조에서는 파일의 `ID` 열을 기준으로 90,067행이 같은 순서인지 확인했다. 최종 예측과 세 예측의 평균 사이 최대 절대 오차는 약 **2.22×10⁻¹⁶**으로, 부동소수점 오차 수준에서 일치했다. 파일명만 보고 추정한 앙상블이 아니라 제출 산출물에서도 평균 결합을 확인한 것이다.

다만 정답이 없는 예측 파일로는 대회 AUC나 앙상블의 개선 폭을 재계산할 수 없다. 기존 포트폴리오의 상위 3%·본선 진출 기록과, 학습 로그의 평가 AUC를 서로 다른 근거로 구분한다.

## 7. 담당 역할, 배운 점과 남은 과제

기존 프로젝트 기록에서 정리한 내 역할은 파생변수 설계, 전처리·결측 해석, 모델 탐색과 검증 결과 분석이다. 발표자료는 팀의 분석·최적화·앙상블 과정을 설명하며 개인별 세부 분담을 추가로 명시하지 않는다.

이 프로젝트에서는 자료형과 결측값을 시술 과정의 맥락에서 해석하는 기준을 배웠다. 범위형 횟수, 함께 비어 있는 배아 변수, 한 정보를 수치·범주로 다르게 표현하는 방식을 점검하며 피처를 설계했다. 이후에는 학습 코드뿐 아니라 변환 규칙, fold별 점수와 모델 설정을 같은 실행 단위로 남길 필요가 있다.

추가로 확인할 과제는 연령대·시술 유형별 오류, 예측 확률 보정, 학습·평가 집단 차이에 따른 성능 유지 여부다. 비율 변수의 분모 처리와 테스트 전용 범주 처리도 코드로 명시해야 한다. 이 항목들은 후속 점검 방향이며, 이미 검증된 성과로 제시하지 않는다.

## 8. 보존 자료와 재현 범위

현재 [GitHub 프로젝트 폴더](https://github.com/SeokHwanHong/Projects/tree/main/lg-aimers-6-infertility)에는 README, 피처 설계 기록, 발표 파라미터, 학습 로그와 집계 그래프를 정리한다. 원본 의료·시술 행 데이터와 개별 ID별 제출 예측은 본문에 공개하지 않고 집계 결과만 사용한다. 수료증은 프로젝트 분석 자료와 분리한다.

이번 압축파일에도 최종 `.py`·`.ipynb` 학습 코드는 없다. 모델을 처음부터 재학습할 수 있는 저장소라고 설명하지 않으며, 지금 확인 가능한 범위는 EDA 집계·실험 기록·로그·최종 예측 결합 방식이다.

근거는 팀 발표 PDF 「뭉치네밥버거_ppt」 3~8쪽, 데이터 명세, 전처리 중간 CSV, 텍스트 메모, CatBoost 로그와 제출 CSV다.
